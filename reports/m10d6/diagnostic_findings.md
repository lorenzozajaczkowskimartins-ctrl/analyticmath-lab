## P0 — Resource and Hessian route truth

1. **The scalar-field limit is 32 inclusive.** `analyze(...,variables)` rejects 33/3000 variables before derivatives; it does not reject exactly 32. Exactly 32 can build the dense symbolic Hessian and all compiled derivative callables before domain/exact-search resource checks. No public memory keyword is available on this analyze signature. Source: `src/multivariate_analysis.jl:35-47,283-321`; existing 33-variable guard test: `test/multivariate_regressions.jl:44-46`. Proposed target: Scalar-fields / Supported dimensions.
2. **A supplied 3000-dimensional Hessian belongs to the matrix normal-mode route, not expression analyze.** A Float64 3000² payload is 72,000,000 bytes (68.66455078125 MiB); the direct modal preflight estimates 1,728,000,000 bytes (1.6093254089355469 GiB), exceeding the default 536,870,912 bytes. Arithmetic was calculated with Python. `max_memory_bytes` is a real public keyword here; estimate is not peak RSS. Sparse inputs still densify. Source: `src/mechanics/normal_modes.jl:149-186,202-253`; test: `test/m10c_partial_modes.jl:4-17` (3000 with explicit 1024 bytes, not a default-budget 3000 execution). Proposed target: Normal-modes / Memory.
3. **Direct-matrix preflight does not cover upstream adapters.** Atomistic normal modes traverse and scale the supplied Hessian before forwarding to the memory gate (`src/atomistic/modes.jl:24-50`). Mechanical overloads first construct linearization matrices (`src/mechanics/normal_modes.jl:31-77,265-279`). Document scope precisely; potential future early adapter preflight is not implemented or freshly tested here.
4. **Fixed exact-algebra budgets are internal.** Degree 64, coefficient bits 4096, cumulative work 200000, AST nodes 512/depth 48 become unknown/resource_budget. They are not configurable public RAM limits and do not bound expression construction/compilation (`src/core/exact_algebra.jl:1-46`; `src/real_analysis.jl:130-164`). Do not invent a keyword or promote `_RA_*` constants into API.
5. **The scalar stationary-search note can suggest an ineffective recovery.** The final `raw===nothing` note says to provide finite bounds even for `:resource_budget` or `:unknown_domain`; numerical fallback only runs for `method==:unsupported` with an established domain. Bounds also trigger the seed-product guard after symbolic derivative construction, including when exact candidates already exist (`src/multivariate_analysis.jl:304-338`). Proposed target: Errors-and-status / Why bounds may not help. No source change made.
6. **Pair-output controls bound output, not whole computation.** Public `max_pairs` and `max_bytes` use `64*pairs_count + sizeof(Int)*(|A|+|B|)` after selection arrays are made. Refusal returns unknown/unavailable, not an exception. RDF/coordination avoid the full pair list but still traverse quadratically. Fixed-width estimate is not valid as a strict peak-RSS bound for arbitrary precision/backend quantities (`src/atomistic/core.jl:87-123`; `test/m10c_atomistic_scale.jl:9-21`). `mdcheck` exposes `max_pairs` only, not `max_bytes` (`src/atomistic/inspection.jl:31,60`).
7. **No generic public partial-Hessian/large-state escape hatch.** `ControlledModes.partial_chain` is a chain-specific maintainer example; `_scale_ode_problem` is internal. Neither removes the public scalar-field/FirstOrderODE dimension limits. Sources: `examples/scaling/partial_modes.jl:1-75`, `src/dynamical_systems/scaling.jl:1-42`, `src/dynamical_systems/integration.jl:14-19`. Proposed target: Scaling / Maintainer experiments versus public API.
